# PCM и память сэмплов (A19/A11c)

AudioBackend.getSamplePCM возвращает переносимые данные: sampleRate,
length, duration, массив каналов Float32Array. Это независимая копия;
редактор не получает AudioBuffer и не может изменить играющий буфер.
Метод и getSamplePeaks загружают только запрошенный SHA-256, даже до
setPatch. Ошибка отсутствующего/битого файла отклоняет Promise; редактор
показывает причину и повторную загрузку. Смена записи сбрасывает старую
волну/выделение, поздний ответ не заменяет новое содержимое.

## Кэш и загрузка

DecodedAssets хранит до 256 МиБ PCM и 1024 записей на экземпляр движка.
Один декодированный файл — до 64 МиБ (length × channels × 4).
Кодированный файл также ограничен 64 МиБ. Проверка размера PCM происходит
после decodeAudioData: это не гарантия пикового потребления браузерного
декодера. Прежде чем импортировать очень длинную сжатую запись, её следует
обрезать; контейнерный preflight/потоковое декодирование ещё не реализованы.

Текущий патч удерживает используемые его треками записи, в том числе для
других сцен. Экспорт удерживает записи звучащих партий на всё время рендера;
библиотечное preview — до очистки голоса. Незанятые записи вытесняются LRU.
Если занятые записи не помещаются, загрузка явно отклоняется до запуска
транспорта/сохранения WAV. Неудачный допуск не вытесняет старые записи.
Смена патча снимает прежние удержания; повторное освобождение безопасно.

Одновременные запросы одного SHA используют одну Promise. Декодирование
разных записей последовательно, очередь ограничена 64 запросами. Отказ
декодирования удаляется из очереди: повторная попытка может загрузить файл,
появившийся в библиотеке позднее. ensureSamples удерживает весь свой набор
на время подготовки, а не только очередной загружаемый файл.

WAV подготавливает ассеты только партий, в которых есть слышимые события.
Отсутствующий сэмпл выключенной/пустой партии не мешает рендеру других.
Скрэтч и прослушивание выделения загружают основной сэмпл своей дорожки.
Отпускание скрэтч-пэда отменяет ещё не завершившийся запуск иглы.

Подготовленные reverse/loop-регионы имеют отдельный общий LRU 64 МиБ /
32 записи вместо восьми потенциально огромных копий каждого исходника.
Кэш 64 пиков ограничен 1024 записями. Диагностика транспорта показывает
байты и число декодированных записей, размер очереди.

## Границы утверждения

256 МиБ ограничивают сильные ссылки кэша, а не память всего приложения.
Играющий источник после смены патча может ещё удерживать вытесненный
AudioBuffer. Копия PCM редактора, данные scratch worklet, временные буферы
decode/render/WAV, IR и внутренние структуры браузера учитываются отдельно.
Кэш регионов также не ограничивает число копий, уже удерживаемых голосами.
Потоковое чтение, общий process memory budget, бинарный desktop IPC,
capabilities и платформенные I/O-адаптеры остаются следующими пунктами A19.
Формат музыкального JSON не изменился: schema v46.

## Проверки

test:assets проверяет реальные PCM-копии и независимость каналов, один
decode при конкурентных запросах, агрегатный предел, освобождение старого
патча, отсутствие лишней загрузки при WAV, повтор после отсутствующего
файла и UI восстановления волны. Чистые тесты проверяют lease/LRU,
атомарность отказа, ограничение очереди/числа записей и восстановление
после ошибки декодера. Golden и DSP-контракт должны сохранять прежний звук.
