# Дизайн-философия barlow

Документ фиксирует архитектурные решения, принятые при проектировании
инструмента. Изменения сюда — только осознанные, вместе с обсуждением.

## Принципы

1. **Патч — данные.** Всё музыкальное состояние — сериализуемый JSON.
   UI, движок и ИИ-агент работают с одной моделью.
2. **Слои заменяемы.** Web Audio сегодня → Rust-движок потом; IndexedDB
   сегодня → файловая библиотека потом. Формат патча — контракт, слои под ним
   меняются без него.
3. **Сложность под капотом.** Вложенность компонентов + уровни детализации
   UI: на каждом уровне оперируем ограниченной сложностью.
4. **Редактируемое — в JSON, контент — в библиотеке файлов.**
5. **Любой параметр — точка, к которой можно подключить источник сигнала.**
6. **UI-состояние (что раскрыто, что свёрнуто) — не музыкальные данные**,
   хранится отдельно от патча.

## Сэмплы и бинарный контент

Проблема: аудио в JSON (base64) раздувает патч до десятков МБ — git-диффы,
localStorage и открытие патча умирают.

Решение — ссылочная модель:

- `sampleId` = SHA-256 содержимого. Патч хранит только ссылки.
- Библиотека: папка `samples/` + индекс `samples/index.json` с метаданными
  (промпт, модель, сид, длительность, теги). Хеш даёт дедупликацию и
  переиспользование между патчами.
- Переходный период (до Tauri): контент в IndexedDB, метаданные в индексе.
- ИИ-генерация пишет в библиотеку: сгенерила → файл → слот получил ссылку.
- Экспорт патча = zip: `patch.json` + использованные сэмплы.
- Исключение — маленькие редактируемые данные (кривые, таблицы частот):
  им место в JSON, это данные, а не контент.

Слот сэмпла на треке: `sampleId` + параметры воспроизведения (старт, длина,
питч, слайс). Трек-сэмплер — отдельный тип источника звука наравне с
осциллятором; шкала маппит ноты либо в слайсы, либо в транспозиции.

## Уровни детализации UI

- **Свёрнутый трек**: одна строка — имя, громкость, индикатор позиции.
  Экран вмещает весь ансамбль.
- **Норма**: нотный стан + основные параметры.
- **Все параметры**: редкие (фильтр, атака, падение тона, фаза) — за ссылкой
  «ещё…».

Группы параметров схлопываются по отдельности. Состояние раскрытости —
UI-состояние (см. принцип 6).

## Паттерны, сцены, цепочка (переиспользование эскизов)

Модель арранжмента — по духу сессия Live, уложенная в иерархию компонентов:

- **Паттерн** — именованный рисунок дорожки. У трека их список (A/B/C…),
  активный выбирается сценой. Паттерн общий для всех сцен, где играет:
  правка меняет его везде. Независимая вариация — форк (ПКМ по чипу),
  лишние эскизы удаляются в «ещё…». Партия = ноты + свои ручки.
- **Сцена** — снимок ансамбля ссылками: какой паттерн играет каждый трек.
  Переключение одним движением, квантованно к границе цикла. Создание
  сцены сразу делает её активной.
- **Цепочка** — порядок сцен с длинами в тактах: арранжмент от начала до конца.

Вариации — **fork**: дублирование паттерна с правками; связь «форк от»
хранится для навигации. Живое наследование (родитель + переопределения) —
осознанно отложено до стабилизации формата: диффы сложны и легко ломают
ожидания.

### Владение параметрами: инструмент / трек / эскиз

С v41 громкость партии — множитель фейдера дорожки, а не абсолютный
override. Миграция сохраняет слышимые уровни; подробности —
docs/ux-controls-v41.md. Скалярные диапазоны/единицы/владельцы заданы в
src/parameters.ts; история правок вынесена в application service.

С v34 модель трёхсущностная, вопрос «чьё это свойство?» имеет три ответа:
**инструмент** (тембр одной ноты), **дорожка** (поток нот и комната) и
**эскиз** (партия). Инструмент — сущность патча (`patch.instruments`),
дорожка ссылается по `instrumentId`; по умолчанию экземпляр у дорожки
свой. Синтез получает слитый вид (`SoundingTrack`), движок и формат
голоса не знают о разделении. Шкала и тоника намеренно остались на
дорожке: стан общий для всех партий «прибора», строй у нас отвязан от
инструмента. Пресет библиотеки (сентябрь 2026) приносит только тембр
(инструмент + эффекты/моно/моды) и несущую — и несущую только треку
без нот: регистр («бас» от 55 Гц) — часть тембра, но у сыгранного трека
тоника уже часть музыки. Шкалу пресет не трогает никогда: интервалы —
выбор пользователя, а не тембра.

**Шаринг инструмента в интерфейсе убран (ревизия сентябрь 2026):**
идея «один инструмент звучит в нескольких дорожках» оказалась
неочевидной — правка тембра с одной дорожки молча меняла другие.
Теперь правка с дорожки при общем инструменте делает copy-on-write
(`App.changeInst`): дорожке отвязывается своя копия, соседи не задеваются.
Ссылка на общий инструмент в данных остаётся валидной (старые патчи,
импорт) — это деталь формата, не интерфейса.

- **На инструменте** (вью «инструмент» карточки, вкладки «источник /
  огибающая / тембр»): волна (v39: таблица строк-операторов — множитель,
  громкость/глубина FM, форма, хвост, маршрут — плюс большой канвас суммы
  и правая панель слоёв: унисон, вибрато, форманты, заготовка) или сэмпл
  и его настройки (режим, зёрна, скрэтч-жест), огибающая ноты
  (атака/плато/спад) с ручками на графике, падение тона, фильтры.
- **На дорожке** (строй и время партии — в тулбаре стана: шкала-выпадашка,
  тоника, длина ноты, фаза; вью «трек» — сведение и «комната» +
  «сайдчейн»): громкость/пан как база, фаза, шкала и тоника, эффекты
  (комната одна — все партии в неё играют), арпеджиатор, сайдчейн, моно,
  мастер-выключатель. Тоника и фаза живут в тулбаре стана рядом со
  шкалой и «нотой»: это ручки рисования и строя, а не микса — панель
  «трек» остаётся чистой комнатой. Длина ноты (сетка рисовалки) — там же,
  в тулбаре стана.
- **На эскизе** (вью «эскиз» — по умолчанию: чипы в шапке плашки
  эскиза, ручки партии, стан, кривые, модуляции): рисунок нот, длина
  цикла, шаг партии, громкость и панорама партии, вход/выход в сцену,
  мьют, модуляции. От эскиза к эскизу меняется «как играется», а не
  «как звучит инструмент». Чипы эскизов — шапка плашки: выбор эскиза
  и настройка эскиза в одном блоке.
- Шаг (`rate`) с v33 живёт на эскизе (раньше — на треке с
  переопределением); нормализация переносит старые патчи.
- Если когда-нибудь понадобятся эффекты на эскизе, механизм готов:
  цепочка трека пересобирается по сигнатуре (mods+fx), достаточно
  включить эффекты эскиза в сигнатуру.

Кросс-патчевое переиспользование — **библиотека компонентов**: паттерн,
инструмент, шкала, (позже) суб-патч эффектов сохраняются как маленькие
файлы-компоненты и вставляются в любой патч. Это тот же механизм суб-патчей,
применённый к музыкальному материалу.

## Модуляция и автоматизация

С v40 период синхронизированной модуляции хранится как `beatsPerCycle`
и переводится в Гц общим `modRateHz`. Тоника тонального сэмпла принадлежит
инструменту (`rootHz`), тоника партии остаётся на дорожке; mapping включается
`keyTracking`. Контракт и намеренные изменения звука — docs/audio-contract.md.

**Кривые партии (v35).** На эскизе можно нарисовать кривые громкости,
фильтра (60…12 кГц, лог) и панорамы по ходу цикла —
`Pattern.automation: {target, points[{t,v}]}`. Значение — доля от ручек
партии (громкость умножается), применяется на границе каждого шага;
во время перехода сцен громкостная кривая уступает рампам fadeIn/fadeOut.
Редактируется дорожкой под станом (`AutoLane`): та же сетка шагов,
точки прилипают к границам шагов (Shift — свободно), на цели «громкость»
по краям — рампы fadeIn/fadeOut, тянутся за вершину (это те же поля
эскиза; движковая семантика не меняется: кривая повторяется каждый цикл,
фейд — раз на границе сцен).

**Темп-карта (v35).** Пункт цепочки может задавать свой bpm
(`ChainItem.bpm`); на границе сцены часы треков пере-якорятся, плейхед
идёт от `engine.currentBpm`. Пусто — темп шапки патча.

Философия: не рисовать кривые, а **подключать источники к точкам параметров**.

- У адресуемого параметра кнопка «~»: выбрать источник и глубину.
- Источники первого класса: LFO (форма, скорость, синхронизация к доле),
  случайное блуждание (S&H), однократная огибающая (для фейдов),
  позже — рисованная кривая как ещё один тип источника.
- Первые адресаты: панорама (новый параметр трека — пинг-понг = LFO на pan),
  громкость, фильтр, питч, тоника.
- Данные компактны и сериализуемы: `{target, source, depth}` — агент-ИИ
   управляет модуляцией одной правкой патча.
- Когда появится граф узлов, источник модуляции станет узлом с выходом —
  система не переделывается, а развивается.

## Экосистема плагинов и низколатентный вывод (решение)

**VST/VSTi отвергнуты** — они противоречат идеологии инструмента:
MIDI по построению 12-тонное, микротон через pitch-bend — костыли;
нужных эффектов не так много, чтобы тащить тонну легаси. Направление —
**швейцарский нож встроенных инструментов** (voices.ts: осцилляторы,
FM, Karplus-Strong, супер-пила, форманты, орган, модальные, сэмплер,
гранулярный, скрэтч): закрыть любую стандартную потребность родным
тембром. MIDI-уровень функционала (арпеджиаторы и прочее) делается
своими эффектами над нотами, без MIDI-легаси. Собственный формат
плагинов — возможное будущее, осознанно не сейчас.

**ASIO-переезд**: Web Audio живёт внутри WebView2, выводится частично —
переезд означает перенос всего графа в Rust-процесс. Подготовка:
публичная поверхность движка формализована контрактом `AudioBackend`
(audio/backend.ts) — UI не знает про Web Audio; формула тайминга
выделена (audio/timing.ts) и портируется в Rust один в один; синтез —
единая точка `triggerVoice` (audio/voices.ts). Сверка реализаций —
golden-рендеры: `npm run golden` (fixtures/golden.json), оффлайн-рендер
и live используют один triggerVoice.

## Порядок внедрения

1. Схлопывание UI (уровни детализации).
2. Паттерны + сцены + цепочка — ядро композиции.
3. Модуляция (pan первым адресатом).
4. Сэмплы + ИИ-сэмплер поверх библиотеки компонентов.
