# Нарезка и взаимное глушение (v48)

## Недеструктивные фрагменты

`Instrument.sampleSlices` — до 64 записей `{id, name, sampleId,
sampleName?, start, end}`. Границы в секундах исходного файла, 0 ≤ start <
end ≤ 3600, длина не менее 1 мс. ID уникален внутри инструмента; SHA-256 имеет общий контракт
ассетов. PCM не копируется. Смена основного сэмпла не переназначает старые
фрагменты: каждый ссылается на свою запись. Общий сборщик ассетов включает
эти ссылки в preloading, pinning и переносимый ZIP, даже без основного сэмпла.

`Note.sliceId` выбирает фрагмент вместо зоны/root-slot. Тоника инструмента
и key tracking сохраняют обычный смысл; round-robin зон для фрагмента не
вызывается. Сначала выбираются запись/границы фрагмента, затем применяются
locks ноты: например, можно уточнить старт. Прямой, granular и scratch
используют общий выбор. Фрагмент сам по себе не меняет скорость, длину
ноты, ADSR или режим loop. Это нарезка, не time-stretch.

Удалённый ID остаётся у ноты, чтобы undo восстановил связь. В sample-режиме
такая нота молчит и не попадает в event plan; UI показывает «фрагмент
удалён — нота молчит». Он не заменяется полным исходником. В режиме wave
ссылка не действует и сохраняется до возвращения к сэмплеру. Перенос,
копирование и дублирование сохраняют sliceId вместе со всем Note.

Редактор источника позволяет добавить текущее выделение или равномерно
нарезать файл на 2–64 части, дать имя, изменить границы, прослушать и удалить
фрагмент. «Новый эскиз: фрагменты по порядку» создаёт отдельную партию:
по одной ноте длиной в шаг, на первой высоте текущей шкалы; назначает её
выбранной сцене. Старый эскиз сохраняется. Входной шаг наследуется от
текущей партии. Это исходная последовательность для редактирования, не
автоматическое восстановление исходного темпа брейка. Предел — 128 партий.
Создание/удаление/назначение — команды undo, имя и границы — жесты.

Зерно ограничивается длиной региона с учётом максимальной скорости
(pitch drop и вибрато), чтение дополнительно ограничено его концом.
Прежде длинное быстрое зерно могло захватить PCM за обрезкой; это
исправление меняет такие гранулярные патчи. Контракт проверяет тишину
в коротком фрагменте при громком сигнале непосредственно после него.

Preview региона принимает готовый SoundingTrack: можно прослушать файл
фрагмента, отличный от основного. track.id сохраняется для маршрута в
цепочку, параметры инструмента не перезаписываются повторным lookup.

## Choke groups

`Track.chokeGroup` — необязательный номер 1–16; `chokePriority` — 0–16.
Новая допущенная атака группы мягко глушит предшествующие голоса группы
до их FX. Эхо/реверберация остаются частью цепочки. `mono` действует внутри
одного трека и показан рядом в настройках. Выключенные/замьюченные треки
не конкурируют за одновременную атаку.

Одновременные атаки (погрешность менее 1e-7 с) разрешает общий
`selectChokeEvents`: больший приоритет побеждает, при равенстве — нижний
трек в патче. Все одновременные ноты победившего трека сохраняются, поэтому
аккорд не распадается. Выбор одинаков для live и WAV; WAV отбрасывает
проигравшие события до выделения их цепочек и оценки голосов. В live трек
без цепочки из-за бюджета не заглушает доступный трек. Это явно
диагностируемая перегрузка, при ней полная parity не обещается.

Хронологическое глушение использует MonoVoices с отдельным пространством
групп. Поздний duck больше не переносит `source.stop` позже уже известного
stopAt: это важно и для фактической тишины, и для бюджета голосов.

## Проверка и пределы

`npm run test:slices` сравнивает PCM с явно выбранными файлами/границами,
проверяет locks, отсутствующий ID, ZIP/ассеты, негативные входы, приоритет,
фактическое исчезновение хвоста, запрет продления остановленного источника,
одинакового победителя live/WAV и UI с отменой/повтором.

Не входят: поиск транзиентов, warp/time-stretch, автоматическая оценка BPM,
клавиатурная раскладка фрагментов по диапазону, многослойные инструменты,
полная parity переходов сцен. Нарезка и choke не заменяют эти следующие
пункты плана.
