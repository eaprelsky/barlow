# Дебаг-мост (ИИ-агент ↔ приложение)

MCP-интерфейс для агента: живое управление патчем и прослушивание.

- MCP-сервер `scripts/mcp-barlow.mjs` (подключён в `.zcode/config.json`,
  локально, в gitignore) поднимает WebSocket-хост `127.0.0.1:22756`
  («barlow» на телефоне; порт — `BARLOW_BRIDGE_PORT`). Приложение
  (`src/bridge.ts`, интеграция в App) подключается только после ввода
  кода в «Настройки → Звук и подключения → Внешний помощник». Код выдаёт `live_status` и
  действует до перезапуска MCP. По умолчанию разрешено только чтение;
  редактирование и транспорт включаются отдельно. После настройки
  приложение переподключается при временном отсутствии хоста. Другую
  вкладку заменяет только клиент, подтвердивший код; старая вкладка
  останавливает reconnect, чтобы они не вытесняли друг друга по кругу.
- Поток: приложение шлёт hello/patch/transport/notes (ноты — `noteSink`
  движка, только live-планировщик, оффлайн-рендер молчит; частоты хост
  считает по патчу сам). Команды с ack: `set_patch` (замена, как импорт
  файла), `set_param` (JSON-указатель RFC 6901), `transport`
  (play/stop/scene/bpm).
- Все агентские правки идут через перехваченный setPatch/setPatchStep —
  undo-история общая с ручными. Путь `set_param` валидируется на копии
  патча ДО setPatch: исключение в апдейтере уронило бы рендер уже после
  положительного ack (грабли, пойманы smoke-bridge).
- Тулзы MCP: `analyze_patch`/`probe_sound` (по JSON-файлу; probe — таблица
  «время → частоты + RMS» оффлайн-рендера) и `live_*` (status/patch/
  set_param/set_patch/transport/notes); `probe_sound {live:true}` рендерит
  текущий патч моста.
- Смоук: `npm run smoke-bridge` — мост+vite+headless-браузер, проверяет
  круг (hello, set_param → localStorage, отказ битого пути, play → события
  нот, stop). Порт смоука свой (22856), приложению подсовывается через
  `window.__BARLOW_BRIDGE_PORT`.


## Граница соединения (A14, после v44)

`src/bridgeProtocol.ts` используется браузером и Node-хостом (Node 24,
встроенное удаление TypeScript-типов). В начале оба участника обмениваются
одноразовыми nonce; HMAC-SHA-256 связывает роль, оба nonce и набор прав.
Код из 128 случайных бит не передаётся по WebSocket. Браузер отправляет
патч только после проверки proof хоста. Новый nonce хоста делает старый
proof непригодным для нового подключения; разделение ролей предотвращает
отражение клиентского proof в ответе сервера.

Код хранится в `sessionStorage` текущей вкладки, отдельно от JSON проекта.
«Отключить и забыть код» закрывает соединение и удаляет запись. Смена
прав применяется кнопкой подключения. Хост и браузер независимо проверяют
разрешения. Агентские правки — отдельные шаги undo; `set_param` сначала
строит копию, проверяет весь получившийся патч, затем нормализует и
применяет его. `constructor`, `prototype`, `__proto__` и унаследованные
поля запрещены в JSON pointer до обхода объекта.

Хост принимает Origin production-сайта `https://barlow.eaprelsky.ru`,
локального HTTP Vite (`localhost`/`127.0.0.1`) и Tauri localhost.
Пустой/null Origin и сторонние сайты отклоняются до подключения.
Лимиты: 8 неподтверждённых сокетов, 5 с на handshake, 4 КиБ handshake,
8 МиБ полный frame, 128 ожидающих команд, 512 событий в пакете и
4000 записей истории нот. Переподключение/закрытие отменяет ожидающие
команды и очищает снимок, чтобы MCP не показывал старый проект как живой.

Это локальная граница доверия, не защита от процесса с полным доступом
к учётной записи или XSS внутри самого barlow. Браузер может дополнительно
запросить разрешение на локальную сеть. CSP и OS-backed хранение ключей
платных AI-провайдеров остаются отдельной работой.

Проверки: `npm run test:bridge-security` — реальные WS-клиенты, origin,
proof/replay/capabilities, замена вкладок, frame bounds и cleanup;
`npm run test:bridge-ui` — явное подключение через интерфейс, запреты прав,
JSON pointer, поддельный хост без утечки патча и клиентская проверка прав.
`npm run smoke-bridge` явно передаёт сессионный код только тестовой вкладке.
