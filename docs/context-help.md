# Контекстная справка — контракт интерфейса

## Пользовательский сценарий

Любая кнопка «?» и F1 включают один режим: курсор с вопросом, подсветка
элемента под мышью, щелчок открывает карточку. В карточке: что это,
как пользоваться, выразительный результат или пример. Объяснения хранятся
локально и не требуют ИИ или сети. По умолчанию карточки скрыты.
«Гиды» в шапке — отдельное меню пошаговых задач.

Esc сначала закрывает карточку, затем режим; F1 переключает режим.
Tab позволяет выбирать элементы, Enter/пробел открывают объяснение
сфокусированного элемента. Кнопки самой карточки доступны с клавиатуры.
Повторяющиеся элементы привязаны к фактическому DOM-узлу и своей дорожке.

В режиме справки pointer/click, клавиши изменения, колесо над полями,
вставка/вырезание/перетаскивание не должны менять проект или запускать
действия. Прокрутка страницы остаётся доступна. После выхода возвращается
прежний фокус. Native dialog не исключение: его «?» открывает справку,
карточка переносится порталом внутрь верхнего dialog. Esc в режиме справки
не подтверждает и не закрывает исходное окно. Переход в гид доступен вне
native dialog; внутри остаётся полное текстовое объяснение.

## Архитектура и покрытие

- `explanations.ts` — предметные понятия и команды: `{title, text, how?, example?}`.
- `parameterHelp.ts` — обязательный текст для каждого `ParameterId`; полноту
  обеспечивает `Record<ParameterId, string>`. Это слой интерфейса, а не DSP.
- `cards.ts` — совместимые карточки существующих групп и ссылки на гиды.
- `data-help` — устойчивый ID объяснения, независимый от текста и `data-ob`.
  `Knob` и `NumField` принимают тот же ID через `help`.
- `helpResolver.ts` — единое разрешение: собственное объяснение → авторское
  описание/подсказка конкретного контрола → ближайшая документированная группа.
  Подписи, иконки, линии графика и пустое место группы объясняются в контексте
  этой группы. Вспомогательные графические части не требуют дублирования текста.
- Имена и описания пресетов передаются как текст; значения полей ввода,
  особенно ключи и коды, не читаются для составления справки.
- `helpMode.ts` — единая команда включения; App выключает конкурирующий гид.
- `PointHelp.tsx` — выбор, блокировка действий, курсор, размещение и фокус.

Новый визуальный элемент или логическая группа должны иметь осмысленную
справку. Для нового действия — собственный `data-help`; для декоративного
потомка — наследование ближайшей группы. Нельзя считать общий текст
«рабочее пространство» покрытием неизвестной кнопки: runtime-аудит считает
такой случай пропуском. Сложный новый параметр описывается через результат
для музыканта, без требования знать технический термин заранее.

`npm run test:help-coverage` проверяет все статические help-ID из компонентов,
отсутствие непокрытых контролов в сценариях, выбор без изменения патча,
точный ввод/undo ручек слоя и макроса, native dialog и клавиатуру.
Отчёт `tmp/help-coverage-live.json` отдельно показывает наследование групп:
это не то же самое, что уникальная авторская статья для каждого DOM-узла.
В библиотеке сотни однотипных кнопок используют общие объяснения действий
и индивидуальное описание тембра. Число DOM-узлов не является числом
независимых пользовательских сценариев или доказательством понятности
без теста с новичком.

## Слои и макросы

Огибающая слоя: три Knob, атака в мс, плато в %, спад в с. Перетаскивание,
Shift, стрелки, двойной щелчок/Enter → число, Escape → отмена текущего ввода.
Макросы: плитки CSS grid с содержимым внутри своей плитки; при ширине
1024 px и открытой библиотеке — две колонки. Назначения раскрываются
независимо, список не вытягивается в одну узкую вертикальную колонку.

Положение макроса показывается в процентах, в JSON остаётся 0..1.
Размах — биполярная ручка. Логарифмические параметры используют октавы,
процентные отображают процентные пункты, остальные — единицы параметра.
При смене цели размах ограничивается её диапазоном. Форма JSON не меняется.

NumField не отправляет повторно уже применённое значение при blur и
возобновляет жест на реальной правке. Это предотвращает пустой шаг undo
после точного ввода в Knob, в том числе при StrictMode/autofocus.


## Переключатель и фильтры дорожек (2026-09-08)

Кнопка «?» — переключатель: повторный клик, Enter или Space выключает
режим, включая открытую карточку. `data-help-toggle` пропускается через
перехватчики PointHelp; остальные контролы по-прежнему защищены.
Кнопки native dialog используют общий HelpToggle и отражают состояние
через aria-pressed. F1 и прежняя последовательность Escape сохраняются.

Строка над дорожками содержит поиск по имени и скрытие мьюта открытой
сцены. У каждого контрола и группы есть предметное объяснение. Это локальное
состояние вида, не поля Patch, не действие undo и не изменение звука.
Поиск — подстрока без учёта регистра и е/ё; фильтры объединяются через AND.
Мьют — только SceneSlot.muted, без трактовки enabled/solo как мьюта сцены.
Переход между сценами пересчитывает вид; фильтры сохраняются до сброса
или добавления трека. Добавление сбрасывает фильтры, показывая новый трек.
При пустом результате есть пояснение и доступный сброс. Порядок не меняется.

Новые сцены получают следующий номер после максимального имени «сцена N»;
пользовательские имена не переименовываются. После «сцена 1» — «сцена 2».
`test:navigation` проверяет нумерацию, фильтры, неизменность патча,
переключатель мышью/клавиатурой и вид 1024/1440 px.


## Сцены и лаконичный экран

Имя редактируется непосредственно в чипе по double click или F2; Enter/blur
подтверждают одним шагом undo, Escape отменяет. Пустое имя не применяется.
Рядом с «+» — «×» для выбранной сцены и переключатель вида цепочки;
режим исполнения «сцена/цепочка» остаётся отдельным управлением.
Инструкции по точкам/Shift и LFO перенесены из постоянных абзацев в
automation-mods. Пустая кривая показывает только статус числа точек.
Предупреждения о потерянной цели и другие ошибки остаются видимыми.

Так же перенесены в справку инструкции по жестам над волной,
тембру отдельной ноты и фрагментам сэмпла. Статусы и ошибки не скрываются.

## Прямой источник слоя

Карточки layer-source-editor, layer-audition-solo и layer-filter-base объясняют
контекст, прослушивание и локальную огибающую. Параметры используют общие
объяснения основного редактора. Гид sound-design обновлён: промежуточное
сохранение больше не требуется. Сценарии нового вида — test:layer-source.

## MSEG v54

Изгиб входящего сегмента — Knob с точным вводом. Удержание и цикл находятся
рядом с графиком; настройки цикла раскрываются после включения. Каждый
контрол имеет mseg-* карточку: различие процентов формы и секунд, релиз
после ноты, короткая нота, полный проход туда-обратно. Постоянная инструкция
под графиком перенесена в справку. Гид sound-design обновлён.

## Управляющие огибающие v55

Цели громкость/высота/локальный фильтр показываются по одной, настройки
остальных продолжают звучать. Новые mseg-target/pitch/filter/depth/base/control
карточки объясняют размах в октавах, свободные концы и границы длительности.
Гиды звукового дизайна включают сценарий райзера.

## Плитки цепочки

scene-tempo объясняет общий/свой BPM и возврат к наследованию без ввода 0.
chain-scene/order/bars/remove/add описывают выбор, порядок, длительность
и действия над вхождением. Карточка панели и гид аранжировки обновлены.

## Движение wavetable v56

wave-motion/scan-mode/scan-cycles и position-lfo/lfo-shape/rate/depth/phase
объясняют проходы на ноту, герцы, границы таблицы и фазу при запуске ноты.
Карточки базовой позиции/прохода различают базовое движение и добавку LFO.
Гид звукового дизайна и карточка wavetable обновлены.

## Поиск по справке

help-search-* объясняют запрос, результаты, выбор дорожки и безопасный переход.
Окно поддерживает вопросик. Подробный контракт — [help-search.md](help-search.md).
