# UX-ревизия barlow — август 2026

Разовый аудит интерфейса по запросу: аккуратность вёрстки, главное меню,
GOMS-оценка задач, выразительность модели («Тьюринг-полнота»), огибающая
и скрэтч, терминология и копирайт. Методики: эвристики Нильсена,
Keystroke-Level Model (GOMS) для типовых задач, анализ выразительности
формальной модели, замеры геометрии по живому DOM (Playwright) и
скриншоты всех экранов.

Материал: 12 скриншотов основных экранов, замеры позиций элементов,
подсчёт контролов в панелях. Всё численное — из браузера, не «на глаз».

---

## 1. Главные выводы

1. **Ядро (стан + эскизы + сцены) — сильное.** Рисование нот, мьют,
   соло, вариации форком — 1–5 секунд на операцию, это уровень хороших
   DAW. Проблемы сосредоточены на периферии: огибающая, скрэтч,
   гранулярный режим — там, где интерфейс превращается в набор числовых
   полей.
2. **Главное меню не сгруппировано по этапам работы** и содержит
   редкую функцию («сэмплы») среди рабочих панелей. Нужна группировка,
   а не только переупорядочивание.
3. **Три зоны «нагромождения»**: вкладка «тембр» (7 контролов подряд
   без групп), вкладка «огибающая» (5 полей с единицами в подписях),
   редактор волны (инструментальная строка + строка гармоники без
   подписей полей).
4. **Выразительность модели высокая, но не «полная»**: любой трек в
   пределах шагового секвенсора с независимыми циклами — достижим;
   сквозная автоматизация, смена темпа внутри пьесы и условные
   переходы — нет (см. §4).
5. Мелкие визуальные дефекты реальны и измеримы (значения слайдеров
   сидели на 8.5px ниже оси ползунка, вкладки 24px высотой с отступом
   4px). Часть исправлена сразу (§7).

## 2. Главное меню

Текущий порядок (вторая строка шапки):

```
[+ трек] [↶] [↷] [файл ▾] [сэмплы] [микшер] [цепочка]
```

Проблемы по частоте использования:

- **«сэмплы»** (библиотека: прослушать/скачать/удалить) — редкая
  операция обслуживания хранилища, стоит между «файл» и рабочими
  панелями. Музыканту она нужна в момент работы со сэмплом — то есть
  в контексте выбора сэмпла (кнопка «выбрать…» в дорожке), а не в
  главном меню.
- **↶/↷ зажаты** между «+ трек» и «файл» — самая частая кнопка после
  play не имеет постоянного места.
- Нет группировки: создание, аранжировка, сведение, обслуживание
  свалены в один ряд без разделителей.

**Предложение** (с разделителями-группами):

```
[+ трек] │ [цепочка] [микшер] │ [сэмплы] [файл ▾] │ [↶] [↷]
  этап:      аранж./сведение      обслуживание      правка
```

- «сэмплы» дополнительно открыть из сэмпл-пикера («библиотека…»), в
  главном меню оставить как вторичную;
- undo/redo прижать к правому краю — у них нет этапа, они всегда;
- «файл» последним в левой группе — редкий, но предсказуемо ищут в
  конце.

## 3. GOMS/KLM: время типовых задач

Модель: клик ≈ 1.2 с (наведение+нажатие), ментальная операция ≈ 1.35 с
(поиск, решение), ввод числа с клавиатуры ≈ 2–3 с. Опытный пользователь,
без ошибок. Оценки консервативные.

| Задача | Путь | Клики | Время | Вердикт |
|---|---|---|---:|---|---|
| Добавить дорожку | «+ трек» → карточка | 2 | ~4 с | отлично |
| Нарисовать 4 ноты | клики по клеткам стана | 4 | ~5 с | отлично |
| Мьют / соло партии | чип M / кнопка S | 1 | ~1.5 с | отлично |
| Вариация (форк) | ПКМ по чипу | 1 | ~2 с | отлично |
| Добавить эхо | «трек» → «эффекты» → «+ эффект» | 3 | ~5 с | хорошо |
| Собрать сцену | «+» сцена → N чипов | N+1 | ~2+N с | хорошо |
| Пункты цепочки | «цепочка» → + → селект → такты | 3–4 | ~6 с | хорошо |
| Сменить инструмент | «трек» → «выбрать…» → карточка → назад «эскиз» | 3–4 | ~7 с | норм, но разрыв контекста |
| Экспорт WAV | «файл» → «записать wav» | 2 | ~3 с | отлично |
| **Атака/спад ноты** | «трек» → «огибающая» → набор 2–3 чисел | 2 + ввод | **~15 с** | **плохо: числа вместо жеста** |
| Падение тона | «трек» → «огибающая» → тянуть график | 2 + драг | ~5 с | хорошо |
| **Гранулярный режим** | «трек» → «инструмент» → режим → 4 поля | 2 + 5 полей | **~20 с** | **тяжело: термины + числа** |
| **Скрэтч-жест** | «трек» → «инструмент» → режим → «записать жест» → жест → «послушать» | 5 + жест | **~25 с** | **плохо: глубоко спрятан** |
| Найти библиотеку сэмплов | «сэмплы» в меню (неочевидно) | 1 + поиск | ~5 с | спорно |

Выводы:

- Худшие задачи объединяет одно: **параметр вводится числом там, где
  человек ожидает жест** (огибающая, гранулы, скрэтч). Интерактивный
  график падения тона уже показал приём: перевод «поля → драг»
  ускоряет операцию в ~3 раза и делает её наглядной.
- Вторая системная беда — **глубина скрэтча**: 4 шага до начала жеста.
  Кнопка скрэтч-пэда заслуживает места уровнем выше (в вью «эскиз»,
  рядом со станом, у сэмпловых дорожек).

## 4. Выразительность модели («может ли всё»)

Формально интерфейс порождает язык: **периодические последовательности
шагов** (алфавит = аккорды с пер-нотными vel/prob/gate) × независимые
циклы треков (дробный rate, фаза) × конечные цепочки сцен с длинами.
Плюс непериодические источники (S&H, перлин) на 6 целей, 5 эффектов,
арпеджиатор, произвольные шкалы в отношениях.

**Достижимо** (покрытие — практически вся электронная, акусматическая,
полиритмическая музыка): полиметрия и полиритмия любой сложности,
форки-вариации, вероятностная музыка, дроны и «тянущиеся» партии
(плато до перебоя), скрэтч, грануляр, аддитивный синтез, ИИ-сэмплы,
арранжмент из сцен.

**Недостижимо в текущей модели** (и это честные границы, а не баги):

1. **Сквозная автоматизация по таймлайну** — фильтр, открывающийся к
   припеву, или громкость, ползущая внутри сцены. Модуляции только
   периодические/случайные; цель «volume/фильтр» качается, но не
   программируется по времени. Путь: рисование кривых на эскизе
   (сцены уже дают опорные точки — рампы fadeIn/fadeOut).
2. **Смена темпа внутри пьесы** — bpm глобален. Ritardando/accelerando
   и рубато невозможны. Путь: точки темпа на цепочке.
3. **Условная логика аранжмента** — цепочка строго линейна и циклична:
   «повторить припев 2 раза, потом мост» выражается только явным
   перечислением. Путь: счётчики повторов у пунктов цепочки.
4. **Live-ввод** — ноты не наигрываются (нет записи MIDI/клавиатуры,
   квантование ввода). Скрэтч-пэд — единственный «живой» жест.
5. **Пер-нотные огибающие** — форма звука задаётся на трек; нота может
   лишь умножить длину (gate). Крещендо внутри одной ноты — никак
   (кроме питч-дропа).
6. **Сложные вероятностные ветвления** — prob per note есть, но
   «если сыграла нота A, не играть B» — нет.

Ответ на вопрос: **строго Тьюринг-полным язык не является** (нет
неограниченной памяти и условных переходов), но по критерию «любой ли
трек» покрытие периодической электронной музыки близко к полному; узкие
места — автоматизация, темп-карта, live-ввод. Это типовые границы
шаговых секвенсоров (у Live/Fruity тот же класс), расширяются
постепенно и не требуют ломки модели патча.

каждой подписи.

## 6. Огибающая и скрэтч — разбор

**Огибающая.** До этой ревизии график показывал только кривую с одной
подписью; значения A/D/S жили в полях справа. Теперь сегменты подписаны
на самом графике: «A 1 мс», «плато 0%», «спад 0.32 с» (+ подпись длины
ноты справа сверху), кнопка «послушать» рядом. Чего по-прежнему нет —
**жеста**: сегменты не перетаскиваются (в отличие от графика падения
тона). Предложение P1: ручки на изломах кривой (драг по горизонтали —
время, по вертикали — уровень), поля остаются для точного ввода. Это
закрывает худшую GOMS-строку (15 с → ~5 с).

**Скрэтч.** Пэд — абстрактная плоскость t→pos с боковой миникартой.
Три проблемы: (1) глубина доступа (4 клика), (2) полотно не похоже на
предмет: музыкант думает «волна + игла», а видит координатную сетку,
(3) результат жеста не слышен во время записи без проигрывания.
Предложение P2: полотно-волна (горизонталь = сэмпл с пиками, вертикаль
= позиция иглы, линия жеста поверх волны), вход из вью «эскиза» для
сэмпловых дорожек, автопрослушивание при записи. Это реджайм-инструмент
— его имеет смысл делать, когда он будет доступен в один клик.

## 7. Исправлено в этой ревизии (P0)

1. Значения слайдеров блока эскиза выровнены по оси ползунка (было
   −8.5px).
2. Вкладки панелей: выше (6/16/8), текст не липнет к границе.
3. На графике огибающей подписаны сегменты со значениями (A/плато/спад)
   — «огибающая в визуальном виде» теперь есть.
4. Копирайт редактора волны: заголовок «редактор волны» (без имени
   трека — карточка и так подписана), подсказки канваса в одну форму
   («выделение — протяни · зум — колесо»).
5. Термин «парциал» → «гармоника» во всех пользовательских текстах
   (кнопки, подсказки, гиды) — музыкально привычнее, технический термин
   остался в комментариях кода.
6. Ранее в этом же спринте: наезд «?»/«трек» на угловые кнопки шапки.

## 8. Роадмап (приоритизированный, не делается в этом заходе)

**P1 — плотность и жесты (наибольший эффект на «нагромождения»):**
- «тембр»: подгруппы «фильтры», «вибрато», «сайдчейн», «арпеджиатор»
  с заголовками/разделителями; арпеджиатор — раскрывающийся блок.
- «огибающая»: поля под графики в той же сетке единиц (мс для коротких,
  с для длинных — единообразно), группа «падение тона» отдельной строкой.
- ADSR-ручки на графике (драг сегментов).
- Редактор волны: подписи полей строки гармоники («номер ×», «громкость %»,
  «форма»).
- Иконки: гибрид «иконка+текст» для шапки приложения (цепочка, микшер,
  сэмплы, файл); в карточках оставить текст — там он читается.

**P2 — редизайны:**
- Скрэтч-пэд: полотно-волна + вход уровнем выше + автопрослушка.
- Гранулярный режим: пресеты-заготовки («пыль», «облако», «лента»)
  вместо четырёх голых полей.
- Меню: группировка из §2 + «сэмплы» из сэмпл-пикера.
- Свойство «качается от» (сайдчейн) — визуальная дуга/стрелка между
  дорожками (сейчас связь невидима).

**P3 — экспансия модели (см. §4):** кривые автоматизации на эскизе,
точки темпа на цепочке, счётчики повторов, live-ввод.

## 9. Иерархия панелей — решение (ревизия сентябрь 2026)

Модель: **блок с лицевой панелью**. Каждый блок показывает лицевую панель
сразу; «под капотом» — лицевые панели блоков следующего уровня. Без
модалок там, где можно вложенную панель.

```
приложение
├─ шапка: темп, мастер-громкость/пан,_transport — лицо всего проекта
│   └─ рэки-панели (микшер, цепочка, сэмплы, файл): раскрылись — работают
│      поверх, закрылись — не мешают
├─ список дорожек
│   └─ «+ трек» — кнопка НАД списком: нажал — трек появился под кнопкой
├─ дорожка (блок уровня 1)
│   ├─ лицо: имя, соло, переключатель «эскиз | трек | инструмент»
│   └─ содержимое = лицевая панель выбранной сущности:
│   ├─ эскиз (блок уровня 2) — партия
│   │   ├─ лицо: чипы эскизов (выбор = заголовок плашки: активный чип
│   │   │   называет то, что правишь)
│   │   └─ под капотом: строка ручек (длина, шаг, громкость/пан,
│   │       вход/выход) → тулбар стана (шкала, нота, заполнить) → стан
│   │       → кривые партии → модуляции
│   ├─ трек (блок уровня 2) — общее для всех партий
│   │   ├─ «общее»: громкость/пан, фаза, тоника
│   │   ├─ «комната»: эффекты; «+ эффект» — у заголовка секции
│   │   └─ «сайдчейн»
│   └─ инструмент (блок уровня 2) — тембр: источник | огибающая | тембр
└─ редактор волны — блок уровня 2 внутри дорожки: раскрылся — остальные
    панели дорожки прячутся, переключение «эскиз/трек/инструмент» его
    закрывает (он не модалка)
```

Правила, зафиксированные этой ревизией:

1. **Заголовок секции слева, его действия рядом с заголовком**, справка
   «?» — у правого края. Никаких «+ …» на противоположном конце строки
   (раньше «+ эффект», «+ модуляция» и вкладки кривых уезжали вправо).
2. **Слово-метка сущности рядом с контролом — лишнее**, если сущность
   уже названа заголовком блока («эскиз» в строке модуляций убран).
3. **Инструмент не шарится в интерфейсе**: у каждой дорожки звучит свой
   инструмент; правка тембра с дорожки никогда не задевает соседей
   (copy-on-write в App.changeInst). Существование общих инструментов в
   данных — деталь формата патча, не интерфейса.
4. **Вкладки одной группы — текст с палками**: «сэмпл | волна»,
   «источник | огибающая | тембр». Никаких рамок-пилюль.
5. **Дефолты вместо выбора**: «+ трек» не спрашивает — синус + 12
   равных полутонов; тембр меняется потом, когда станет нужен.
6. **График = чертёж**: оси подписаны (0/1 громкости, ×2…×16 тона,
   секунды), длина ноты — размерной линией со стрелками; управление
   понятно из курсора (ручки — горизонтальный драг, кривая тона —
   по двум осям), хоткеи — только дублирование.
