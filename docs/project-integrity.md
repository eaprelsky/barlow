# Границы проекта и библиотеки

Перед миграцией входного JSON проверяются поддерживаемая версия, конечный
темп, бюджет размера/глубины структуры, уникальность ID и ссылки инструментов,
эскизов, сцен и цепочки. Старые формы шага до v37 передаются миграции; будущие
версии отклоняются. UI объясняет ошибку и оставляет текущий патч на месте.
JSON-файл ограничен 8 МиБ.

ZIP: не более 128 МиБ сжатых данных, 256 МиБ заявленного распакованного
содержимого, 512 записей, 64 МиБ на сэмпл, 8 МиБ на patch.json и 1 МиБ на
manifest.json. Допускаются только эти два JSON и `samples/<sha256>.<ext>`.
Имена не должны повторяться. Размеры проверяются до распаковки, большая
распаковка выполняется асинхронным fflate. Проверяются manifest, SHA-256
каждого файла и наличие всех сэмплов патча до записи в библиотеку.

Веб публикует импорт одной IndexedDB-транзакцией. Desktop сначала пишет
контент, затем атомарно заменяет индекс библиотеки; сбой может оставить
неиндексированные файлы, но не частично опубликованный импорт. Мутации
библиотеки сериализуются внутри приложения. Это не распределённая блокировка
между несколькими запущенными экземплярами приложения.

Новые desktop-файлы используют полный хеш; чтение старых slug-shortHash
сохраняется. Rust допускает только одиночные имена аудиофайлов, отклоняет
переходы по каталогам, абсолютные пути, device names, alternate streams и
символические ссылки. Существующий файл дополнительно проверяется через
canonicalize. Проверки защищают границу команд приложения; они не обещают
защиту от процесса ОС, который одновременно подменяет файлы.

Экспорт ZIP не пропускает отсутствующий сэмпл молча: сообщает его имя и
отменяет экспорт. Голый JSON остаётся ссылочным форматом без аудиоконтента.

Регрессии импорта входят в `npm run test:audio`: корректный roundtrip,
неверный hash/manifest/path/version, отсутствующий сэмпл, лимит до inflate и
неизменность библиотеки после неуспешных импортов. Файловые правила Rust:
`cargo test --jobs 1 --manifest-path src-tauri/Cargo.toml sample_path --lib`.
